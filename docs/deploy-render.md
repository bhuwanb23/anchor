# Deploy Anchor to Render

Anchor’s **cloud half** (control plane + dashboard) runs on Render. The **agent** stays on each customer’s Linux VPS and is not deployed here.

## Architecture

| Service | Render type | Role |
|---------|-------------|------|
| `anchor-api` | Web Service (Docker) + 1 GB disk | Go control plane, SQLite, WebSockets, `/install.sh` |
| `anchor-web` | Web Service (Docker) | Next.js dashboard |

Default public URLs (service names in [`render.yaml`](../render.yaml)):

- API: `https://anchor-api.onrender.com`
- Dashboard: `https://anchor-web.onrender.com`

## Prerequisites

1. A [Render](https://render.com) account and a GitHub/GitLab repo with this code.
2. A **paid** plan for `anchor-api` (Blueprint uses `starter`). Free instances sleep and drop agent WebSockets.
3. Optional later: custom domains, SMTP, S3 DB backups.

## Deploy (Blueprint)

1. Push this repo (including `render.yaml`) to GitHub.
2. In Render: **New → Blueprint** → select the repo.
3. Confirm services `anchor-api` and `anchor-web`.
4. Apply. Wait until both are **Live**.
5. Open `https://anchor-web.onrender.com` and create an account / sign in.

If service names are already taken on Render, rename them in `render.yaml` and update every `*.onrender.com` env value to match.

## Environment reference

### `anchor-api`

| Variable | Purpose |
|----------|---------|
| `JWT_SECRET` | Auto-generated by Blueprint; rotate in Dashboard if needed |
| `DATABASE_PATH` | `/data/yourplatform.db` on the persistent disk |
| `FRONTEND_URL` | Exact dashboard origin for CORS |
| `PUBLIC_BASE_URL` | Public HTTPS origin for install commands + agent `websocket_url` |
| `BASE_DOMAIN` | Hostname used when `PUBLIC_BASE_URL` is unset (custom DNS setups) |

### `anchor-web` (build-time)

| Variable | Purpose |
|----------|---------|
| `NEXT_PUBLIC_API_URL` | REST base baked into the Next.js client |
| `NEXT_PUBLIC_WS_URL` | Browser WebSocket URL (`wss://…/ws/browser`) |

After changing `NEXT_PUBLIC_*`, trigger a **clear build cache + redeploy** of `anchor-web`.

## Custom domains (later)

1. Attach domains in Render (e.g. `api.example.com`, `app.example.com`).
2. Set on API: `FRONTEND_URL=https://app.example.com`, `PUBLIC_BASE_URL=https://api.example.com`, `BASE_DOMAIN=api.example.com`.
3. Set on web + rebuild: `NEXT_PUBLIC_API_URL=https://api.example.com`, `NEXT_PUBLIC_WS_URL=wss://api.example.com/ws/browser`.

## Smoke checklist

- [ ] `GET https://anchor-api.onrender.com/health` returns OK
- [ ] Dashboard loads over HTTPS
- [ ] Sign up / login works (CORS)
- [ ] Header shows **Live** (browser WebSocket)
- [ ] Create a registration token — install command uses `https://` and your API host (not `http://localhost`)
- [ ] SQLite survives a redeploy of `anchor-api` (disk mount `/data`)

## Agent install note

`/install.sh` is served from the API. Agent **binaries** under `/releases/` are only present after you publish builds into the repo `release/` directory (see Makefile `release` target). Until then, connect-server install may fail at the download step even though the control plane is healthy.

## Local Docker (optional)

```bash
# from repo root
docker build -f control-plane/Dockerfile -t anchor-api .
docker run --rm -p 8080:8080 -v anchor-data:/data \
  -e JWT_SECRET=dev -e FRONTEND_URL=http://localhost:3000 \
  -e PUBLIC_BASE_URL=http://localhost:8080 \
  anchor-api

docker build -f dashboard/Dockerfile \
  --build-arg NEXT_PUBLIC_API_URL=http://localhost:8080 \
  --build-arg NEXT_PUBLIC_WS_URL=ws://localhost:8080/ws/browser \
  -t anchor-web .
docker run --rm -p 3000:3000 anchor-web
```

## Non-goals

- Agent / Docker / Caddy on Render
- Managed Postgres (control plane remains SQLite for this deploy)
- Multi-instance API (in-memory WebSocket hub is single-instance only)
